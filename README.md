# 论文绘图案例库 · paper-plot-library

独立于衰老文献日报的版本 `0.4.4`。从50篇人工种子开始，内部抓取队列曾扩展到55篇；网站仅发布符合研究范围且有可展示正文原图的文章。自动更新
不是“50篇已复现”。没有运行作者代码，也没有安装作者的科学计算环境。

## 先看网站

当前本机预览：<http://127.0.0.1:8765/>。只有预览进程运行时这个地址才可访问。
以后重启，在终端输入：

```sh
cd /Users/xiangzhoufu/Documents/Codex/paper-plot-library
python3 -m pip install .
python3 -m paper_plot_library serve
```

如果系统没有 Python，可在本机 Codex 环境使用其已验证的运行时：

```sh
cd /Users/xiangzhoufu/Documents/Codex/paper-plot-library
/Users/xiangzhoufu/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 -m paper_plot_library serve
```

预览与自动抓取是不同动作：`serve`只构建并预览，不抓取、不调用付费API。
按 Control+C 关闭预览。不要直接双击HTML，浏览器的本地文件权限会阻止JSON加载。

### 网页只保留有正文原图的结果

构建和发布时立即筛选，不等待后台的3次来源核查删除规则：必须有许可允许复制、实际已下载、
SHA256一致、可解码的正文图，才进入公开画廊、索引、公开JSON和输入说明。只有外部链接、
补充图/Extended Data、损坏或缺失图片的记录不公开；不设“全部记录”切换入口。
公开数量按当前数据、领域范围和正文图条件重新计算，不沿用过去快照的计数。
后台仍保留待处理队列，避免把未核查、临时下载失败的文章当作永久不可用而误删。
公开日志不再列出缺图候选的DOI，只保留汇总进度和已发布文章的相关诊断。

有正文图但缺AI、代码、输入说明或期刊指标的文章仍可展示，各项缺口如实标注。
正文预览不代表图—代码—输入已经对应；原先选择的是补充图或别的正文图时，明确区分正文预览和原选图，
不替换原选图的代码/输入证据，也不声称执行或复现。浏览器发现正文预览加载失败时，本次页面也会移除该文章。

## 自动流程

### 研究范围：先符合领域，再比较图片与期刊

本站 `config.json` 显式启用 `research_scope: aging-sequencing-metabolic`：

- 核心：衰老、细胞衰老、寿命、生物学年龄/表观遗传时钟，与二代/三代测序、基因组、转录组、表观组或多组学等同时相关。
- 扩展：糖尿病、胰岛素抵抗、肥胖、代谢综合征/代谢性疾病，与测序或组学同时相关。
- 方法与工具：可迁移的测序、单细胞、空间组学、多组学整合、调控网络、统计计算及组学绘图工具；正式标题/摘要必须支持其方法贡献和组学用途，不强求具有衰老/糖尿病主题。
- 排除：海洋/生态/植物研究、仅成像、仅临床糖尿病、不涉及组学的通用绘图库；普通肿瘤发现也不能仅因用了组学或AI就冒充可迁移工具。

Europe PMC 每批合计最多5页元数据（核心最多2页、扩展最多1页、工具最多2页），核心充足时仍会检索工具。
实际来源处理每批最多5篇：三组均可用时优先3篇核心、1篇代谢扩展、1篇组学工具；缺组时空位回流。
先过滤已收录、重复、冷却、预印本、撤稿及未来日期的候选，再分配名额，不能让无效候选占住工具位置。
硬条件加在标题/摘要字段上，自定义检索式和NCBI回退均不能绕过。
候选预筛、正式DOI元数据复核、付费注释前、入库前、网站构建均执行领域检查；
AI摘要、人工标签、期刊名及图片精美程度不能替代领域依据。
`aging` 使用词边界，不再误命中 `imaging`；普通“患者年龄18—65岁”也不当成衰老研究。

旧记录不符合或缺乏足够领域依据时从公开目录隐藏，保留原始记录和私有素材以便复查；
首次采集按最多50个DOI合并查询正式元数据，避免只凭旧标题误排除衰老图谱或时钟；
该查询计入现有HTTP预算，不调用AI、不下载论文、不算新增或完整来源核查。未查到的记录保留待复核，不编造相关性。
正式元数据核实过的领域判定保留受控主题/方法标签及DOI—标题绑定，公开目录不发布完整摘要。
本地已有正式元数据缓存时，可用 `python -m paper_plot_library scope-refresh --offline` 重新分类旧库；
这只复用历史正式标题/摘要作领域依据，不联网、不调用AI、不改图片/旧注释/录入日期/每日新增和预算，不能替代当次撤稿或来源复查。
缺失或冲突的缓存不当作核实通过；没有本地缓存的GitHub运行仍由上述有预算的正式DOI查询迁移。
只有符合范围的当日新增占5篇名额，旧离题记录不占位；原有收录历史及HTTP/AI用量不清零、不退款。
通用Python模板的默认 `unrestricted` 仅为兼容其他使用者；本项目已显式启用上述硬筛选，不需要再配置API。

默认 `mode: auto` 与 `daily` 都优先发现新文献，旧文章缺代码、输入说明或需要人工检查不再阻塞日更。
首页显著显示当前 UTC 日“今日成功新增 X / 5”、最新采集时间和未达目标的原因；
网页重新部署、旧文章修补、来源检查次数与 AI 成功次数都不算新增。UTC 日在北京时间08:00换日。
`initialize_existing_first` 保留兼容历史配置，但不再作为日更开关；本站默认关闭。

### 每日新增（默认运行）

北京时间每天09:47、15:47、21:47安排三次机会；后两次只补当天不足的名额，已达目标不再采集。
GitHub 每次运行会连续执行多个批次，不再只做一批就退出。每批最多检查5篇新候选、150次 HTTP；
每批保存本地目录与账本并提交、推送 GitHub，最后保存结束状态。上传的新数据提交带 `[skip ci]`，
避免每个数据检查点再触发一遍发布；当前工作流结束时统一发布。采集报错也会尝试保存已有检查点。

领域检索与预筛 → 正式版本/DOI/撤稿及领域复核 → 作者代码声明 → 固定提交静态检查 →
许可允许的官方整图与补充材料 → 输入路径/真实表头 → 入选排序 → 中文学习注释 →
IF/JCR/引用注释 → 持久化目录 → 独立网站。

目标是每个 UTC 自然日成功收录5篇不同论文（不是必须当天发表5篇），不是只尝试5篇。
先核查必要的非AI材料，满足后才生成注释；原图、正式版本、固定作者代码、可靠输入、AI及期刊查询
通过当前材料验收，且至少有一张与网站发布条件完全一致的可展示正文原图，才入库并占成功名额。
只有补充图、缺图、许可不足、损坏图片或未完整的候选都不计成功，继续寻找替代文章；
同日已经检查但未入选的候选不会在后续批次反复扫描，AI格式或临时失败在单篇内最多尝试3次。
确认缺少必要材料的未入选候选保留7个UTC日的冷却窗口，避免每天重扫同一批失败记录；到期可重新核查，不永久误删。
临时网络、AI或配置失败只在当日避免反复扫描，下个UTC日可重新核查，不因修正密钥而再等待一周。
候选正文图、固定代码/真实表头、合格AI注释按阶段保存到受控账本；跨运行继续，不依赖一次性 runner 的私有缓存。
续跑仍重新核实DOI/撤稿、正文许可与版本、作者代码声明及仓库公开性/提交/许可；只复用完整性通过的图片与未变代码快照。
AI注释绑定当前来源、模型及提示版本；已验证且绑定不变时不再次付费。摘要原文、作者代码摘录、提示和密钥不进入阶段账本。
补充文件副本不上传，换 runner 时必要的补充文件仍可能重新获取；成功入库即删除候选草稿。
元数据发现会跳过已收录、移除和冷却中的DOI，按[Europe PMC官方分页协议](https://europepmc.org/RestfulWebService)
继续寻找后页候选，每批最多5页、最多返回100条，仍受总HTTP预算限制。
自动选图优先下载正文图，再按混合面板丰富度排序；人工指定的补充图/Extended图不会被冒充或改名。
期刊查询完成但未匹配时保留“未匹配”，不编造 IF 或分区。
日更批次不修补旧文献，5个来源检查名额都留给新候选。默认每个 UTC 日累计最多
36批/165次AI/1800次HTTP/45分钟；每批仍最多5篇。同日手动或定时重跑不会重置已用或未知保留预算。
升级时仅将旧版保存的12批上限迁移到当前批次数配置，保留已处理批数、HTTP、AI、未知预留与运行时间；
不提高已保存的HTTP/AI/时间额度，较低配置仍有效。这样不会因为12个低消耗批次而在剩余预算充足时过早退出。
达到目标即停止；外部服务失败、可用候选不足或达到安全上限时，可能少于5篇，首页与日志明确显示未达标。
不能保证外部来源每天都提供5篇满足全部条件的论文，不用无图记录或修补记录凑数。

### 旧文献补齐（独立维护）

只在明确选择 `mode: backfill` 或本地 `backfill-session` 时连续处理既有队列，不发现新文献。
它不影响日更资格，也不占每日新增名额。补库固定当时既有记录作为本次队列，
每批最多5篇，旧库维护仍最多12批，其他累计预算同上；同一遍历不会重复处理已核查文章。显式新一轮可能增加费用。
中断后读取账本继续，未知中断用量按保留上限保守占用，不当作0。
真实材料验收与人工精确对应审批分开，不把遍历完成或AI成功当作材料收齐/代码已执行。
连续3轮真实整理仍无法解决的记录进入“需要检查”；预算跳过不算真实失败尝试。
已准入记录，以及旧库中确有可发布正文图的文章，不因代码/输入缺口经多次核查而自动删除。
只有未准入且无可发布正文图的失败候选，才可能在同类必要来源缺口经3次有效核查后清理，Git历史可恢复；
临时网络、限流、预算、密钥/余额、AI格式或期刊服务错误不触发删除，扫描器能力限制也不当作作者缺资料。
公开网站始终直接隐藏没有正文图的记录，不必等待后台删除判定。
复查采取事务式更新：空结果、404、缺图、缺脚本或表头不覆盖上次成功资料；本轮状态与历史有效资料分别显示。
确证撤稿、DOI错配、许可不允许或同资产哈希冲突仍隔离，不因保留政策绕过发布门。离题文章不发布，但不清空后台历史。

### 共同的预算与失败边界

默认每轮最多15次实际 AI HTTP 尝试，每篇最多3次，含传输失败重试和格式校验重试；配置上限可以降低。
默认总 HTTP 上限仍为150次；配置 AI 时先为 AI 预留最多15个请求名额，初始采集 GET
上限为135次。预留只是本地计数限制，不会提前调用或扣费；失败重试计入总请求和 AI 尝试。
达到采集上限后，未用完的 AI 预留名额仍可用于注释；实际是否已调用以日志中的尝试计数为准。
因本地上限跳过 AI 时，实际尝试为0就是未发起付费请求，
不能据此判断账户余额不足。HTTP 401/402/403、429及服务方错误在日志中分别显示。
HTTP 401/402/403，以及缺少或无效的模型、密钥、接口配置，会立即停止本轮余下的付费 AI 队列；
重新发送同样请求不能修正这类配置问题。纠正后再明确运行补齐，不自动无限重试。
停止付费队列后释放未使用的 AI 请求预留，来源采集可继续使用剩余总 HTTP 预算；不恢复本轮付费调用。
格式或暂时错误可在单篇/整轮剩余名额内重试；没有本轮合格证据的论文不发起付费 AI 请求。
AI 重试不能解决图像许可、缺少公开数据或输入说明的问题，AI 成功也不表示材料全部补齐。
调用费用以服务方账单为准，不承诺固定月费、年费或每次都用完上限。
单篇失败不拖垮其它候选；临时中断保留既有可用证据并标明旧状态，只有符合上方来源规则才自动移除。
旧 AI 注释标为待更新并显示最近尝试状态；历史指标可保留已匹配状态，同时注明本轮获取失败。
本轮文献、全文或代码核查失败时，不为该案例发起付费 AI 请求；保留的旧注释标为过期。
日志阶段统计只反映本轮实际检查的状态，不把此前保留的失败状态重复算入本轮。
日志的“自动步骤完成”只说明本轮自动检查完成，不表示所有原图、输入资料或人工对应已经齐全。
每天新增额度用完显示“今日新增配额已用完”，不会误显示成“本轮未启用”。

选文首先满足研究范围，核心衰老优先，扩展与工具保留实际处理机会，再比较脚本、输入、原图可用性、混合图、
期刊偏好和归一化引用偏好。IF/引用数不是研究质量判断。无许可证、第三方原图、
ND/NC等保守链接，不复制。优先完整混合图；不自动猜边界切掉图例和坐标轴。

## 本地配置 API

复制 `.env.example` 为 `.env`，在自己的编辑器中填写，不把密钥发送到聊天。
DeepSeek、EasyScholar、NCBI账户可以沿用，但新项目必须各自配置。不会自动读取原衰老网站的密钥。

- `LLM_API_KEY`、`LLM_MODEL`：DeepSeek密钥和你账户实际可用的模型名。
- `LLM_API_URL`：默认DeepSeek聊天接口；v1只允许已审核的接口主机，不接受任意URL。
- `EASYSCHOLAR_SECRET_KEY`：IF/JCR/CAS。
- `NCBI_API_KEY`、`NCBI_EMAIL`：PubMed备用检索。
- `OPENALEX_API_KEY`：可选；缺失/额度不足时保留引用指标未知。
- `GH_TOKEN`：本地可选GitHub只读令牌，提高公开仓库API额度；不要扩大访问权限。

```sh
python3 -m paper_plot_library check
python3 -m paper_plot_library backfill-session
```

`check`只显示是否配置，绝不显示密钥。`backfill-session`连续处理既有库，`update`只运行单批；均会访问公开接口、下载有许可的小文件，
有AI密钥时会产生账户调用费用。首次可限制为：

```sh
python3 -m paper_plot_library update --mode backfill --bootstrap-batch-limit 1 --max-ai-calls 1 --max-requests 40
```

该命令会实际访问接口，不是离线验收；此轮代码修改没有执行它。`--bootstrap-batch-limit`
控制补齐阶段批次，`--repair-limit` 仅控制后续日更维护名额，两者不是同一个选项。
完整更新参数在 `config.json`。支持补充材料（已获用户确认），默认每篇最多3个、
每文件6MB；不下载整套原始测序数据。ZIP不解包；PDF检查页数与身份标志；
无法核实身份单独标记。缺少模型、密钥或额度不会编造中文解读和指标。

## 目录与命名

- `paper_plot_library/`：Python模块，`python -m paper_plot_library`是本地入口。
- `scripts/cloud_collect.py`：仅用于 GitHub Actions 的连续整理与逐批 Git 保存入口，本地禁止意外上传。
- `web/`：正式前端源码。
- `data/catalog.json`：可提交的持久化案例；不含完整摘要或抓取代码片段。
- `data/ledger.json`：每日配额和待核记录，不能随意删除。
- `data/assets/`：带源哈希名的许可允许原图。
- `site/`：可重新构建的本机预览；发布时再通过 `export` 白名单导出。
- `.ppl/`：私有缓存、补充文件、运行锁；不提交、不整目录部署。发布只上传 `export` 生成的白名单子目录。
- `.github/workflows/site.yml`：GitHub 每日更新与发布工作流；每次结果以 Actions 运行记录为准。
- `docs/acceptance.md`、`docs/iterations.md`：验收范围、真实限制与迭代记录。

## 状态与人工核对边界

网站仅显示有已验证正文原图的文章，不公开候选池或排除记录；画廊和索引使用同一准入条件。
内部整理队列与公开网站分开，后台物理移除仍需有效来源核查，不把一次网络失败当作永久不可抓取。
日更新新候选仍只有达到完整材料准入要求才入库、占用每日成功名额；正文图展示不是完整材料验收。
每篇的原图、代码、输入、AI、期刊指标分别显示，不再用一个“部分完成”概括所有问题。
输入文档笔记、代码读取候选、实际读取的表头分别标注；即便观察到表头，也不等于输入语义、单位或当前选图对应已经核实。
已发布文章仍可能缺代码、输入或 AI，真实接口/来源错误另外提示。没有许可或未取得正文原图的文章不公开。
“未运行”始终保留，原图—代码—输入的“精确对应已核”是另一项严格状态。
