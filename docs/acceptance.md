## 0.3.0 维护验收 · 先补齐当前候选，再进入日更

检查日期：2026-10-11。本轮仅实施代码、界面、配置和离线验证，没有访问真实文献接口、
下载新论文、调用付费 AI、修改真实案例目录或上传 GitHub；已有云端内容未因此自动补齐。

- 项目默认启用 `initialize_existing_first: true`。第一次 `auto` 固定当时全部既有记录为候选批次；
  本批仍有待处理或需要检查记录时，暂停新文献发现，不只检查原来50篇的一小部分。
- 初始化来源整理默认每轮最多20条，但受总 HTTP 150次上限约束；AI 仍是每轮总计最多5次 HTTP 尝试，
  含失败重试，不是20篇分别调用5次。预算跳过不累计为真实未解决尝试。
- 自动材料验收核对真实可用来源、许可与图像文件完整性、固定代码及其来源关系、输入说明、AI和已配置指标。
  它不替代人工精确图—代码—输入绑定，不执行作者代码，也不证明原图复现；期刊查询未匹配不编造指标。
- 连续3次真实整理仍未解决的案例进入“需要检查”，自动模式不持续重试此类案例。
  修正密钥、来源或其它具体原因后，可明确选择 `backfill` 再试；未解决记录不会悄悄排除或变成绿色完成。
- 本批真正收齐材料后，下一次自动运行才转入日更，每个 UTC 自然日最多新增5篇。
  `backfill` 不发现新文献；历史公平修补策略用于初始化完成后的日更维护。
- 首页与日志分别显示本批完成、待处理、需要检查数量及受控原因；只有计数一致且没有未解决缺口，
  才允许显示本批材料完成。真实 API 响应、内部候选状态、密钥和提示词不公开。
- GitHub Actions 使用相同 Secrets，新增 `mode` 选择；日常及定时运行推荐 `auto`。
  上传应先 Commit，Fetch/Pull 合并云端自动数据后 Push，不覆盖云端记录。
- 本地首次小范围联调示例改用 `--mode backfill --bootstrap-batch-limit 1`，不误用日更的 `--repair-limit`。
- 最终274项离线回归通过；前端语法、离线构建、白名单发布导出与差异空白检查均通过。
