## 第二轮：完整自动链与恢复

## 第三轮：真实公开来源

对PRC2-AgeIndex和DiMeLo-seq做精确DOI查询和公开PMC来源检查；没有调用付费AI或运行作者代码。
发现“Figure 1c”未正确识别，以及全角中文括号/主图、扩展图、补充图的编号混淆，已修复。
PRC2展示官方整张Figure1，800×579像素、CC BY4.0；不把整图误称为已核验的c分面截图。
补充PDF加入结构、页数和身份标志检查；ZIP不解包。阶段检查点：115项通过。

## 第四轮：独立交付审查

修复空哈希互相相等导致错误审批、其他脚本输入冒充当前输入、损坏账本继续写入和历史无限增长。
正式核查绑定审核人/时间、固定提交、脚本哈希、原图哈希、输入哈希和该输入实际读取脚本链接。
分类建议对象保持原始不确定性注释，不因`set()`遇到对象而崩溃，不自动进入正式选择目录。
作者代码声明按语句区分，避免把论文引用的工具仓库误认成作者脚本；补充“freely accessible”真实表达。
原始JATS无图号时不按顺序补造图号；保留原MIT版权声明。
原图署名保留JATS中提供的真实作者，而非仅写“论文作者”。
发布仅使用白名单导出，私有缓存/补充材料/用户放入预览目录的其它文件不随网站发布。
阶段检查点：136项通过。

## 第五轮：可用性和真实检索回查

桌面改为固定双列、820px以下单列，详情页与原图查看器加宽。
原图保持比例；标签/放大按钮位于图片下方，不遮盖坐标、图例；支持适应窗口和100%原始尺寸。
修复Logo返回首页和重复读屏播报。宽屏与手机检查结果见验收记录。

真实仅元数据检索首次返回9条正式候选，但全部为未来刊期；这会挤掉较早的可用文献。
修正为请求之前按UTC当天加刊期上限，返回后再作未来日期防守筛查，并提高作者代码检索约束。
继续复测发现无DOI的PMC记录也会占满第一页，已在分页前限制到带DOI的PubMed正式记录并排除综述。
最终真实元数据检索：1次请求返回10条正式候选，日期2026-10-01至2026-10-04；未下载它们的论文或代码。
`update --doi`现在只修补指定已有论文，不会额外发起全库发现；无效DOI在请求前拒绝。

## 0.2.0：全库可用性与公平修补

第一轮拆分资料可用性、人工精确对应和最近接口健康状态。默认展示有匹配官方原图、固定版本作者代码的可浏览案例；
未收齐的种子进入候选池，保留所有记录。原图、代码、输入、AI和期刊指标分别标注；已有字段笔记不冒充真实表头。
AI与期刊失败原因细分为受控枚举，并传到公开运行日志，不发布原始服务响应，不增加格式失败的付费重试。

第二轮实施公平调度并独立审查。默认既有处理名额拆为3个首次检查、2个修补；连续错误退避，资料缺口延后复查。
审查发现 AI 积压绝对优先仍会饿死已生成注释但缺图/输入的案例，改成活动修补按等待时间轮转。
同时修复异常状态类型和不合理远期冷却，冷却时间限定在有效上次尝试后24小时以内。
模拟连续35日、每天新增5篇的队列中，原50个种子最终均获得合成 AI 注释；每轮付费 HTTP 尝试不超过5次。
这些结果验证调度，不证明真实文章资料一定可下载或接口一定成功。

第三轮验收：220项离线测试通过；前端语法、构建、白名单发布导出、差异检查通过。
逐条比较本地53条旧记录的 Python/JavaScript 可用性投影，全部一致；浏览器验证默认案例、候选池、重置及详情输入文档。

## 0.3.0：先完成当前候选批次，再开始每日新发现

用户要求优先把已有候选的缺口处理清楚，因此将默认模式改为两阶段 `auto`。
第一次运行固定当时全部既有记录为本批候选；未处理或需要检查的记录仍存在时，不继续新增文献。
不把最初的50条种子当作50条已经完成的案例，也不把几次 AI 成功作为全库完成的证据。

第一轮实现初始化状态、批次队列和真实材料验收：默认最多安排20条来源整理，
同时遵守每轮总 HTTP 150次、AI HTTP 尝试5次的上限。20个来源名额不是20次付费 AI 名额，
也不保证一轮能收齐20篇。材料验收使用来源、许可、实际文件与摘要等证据，
不降低原有人工精确对应的严格要求；静态收集仍不等于运行作者代码或图像复现。

第二轮加入未解决记录处理：连续3次真实整理仍有缺口时进入“需要检查”，
自动模式不反复尝试这些记录。预算跳过不消耗此次数；用户修正具体问题后，
可明确选择 `backfill` 重试。许可受限、缺少公开输入或未核实作者代码关系不会自动标为完成，
也不通过丢弃文章来提高完成数。本批真正完成后，下一次自动运行才进入最多新增5篇的日更阶段。

第三轮更新公开阶段界面和说明：显示材料完成/待处理/需要检查数量、暂停新发现的原因，
将自动材料完成与人工精确对应、原图复现分开。公开导出只接受受控进度与原因，
拒绝不一致计数、伪造完成、内部批次状态与服务响应正文。旧目录没有阶段数据时保持兼容。
工作流新增 `auto` / `backfill` / `daily` 选项，保持已有 Secrets；本地小范围测试使用
`--bootstrap-batch-limit 1`，避免混淆日更维护的 `--repair-limit`。

网站阶段与安全导出相关29项离线测试通过；最终全套数量与构建结果见[验收记录](acceptance.md)的0.3.0节。
